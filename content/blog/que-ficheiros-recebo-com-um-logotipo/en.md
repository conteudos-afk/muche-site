A logo handover usually arrives as a zipped folder and a message saying «it's all in there». Weeks later, somebody asks for the file to cut vinyl, somebody else asks for a version to sit on a dark photograph, and it turns out it wasn't all in there.

The problem is rarely bad faith. It's that «logo» is a word which, in the head of the person ordering it, means a drawing, and in practice means a set of files prepared for very different situations. It's worth knowing exactly what to ask for before you close the project, because asking afterwards is always slower and more expensive.

## The distinction that explains half the folder

There are two kinds of image file, and almost every confusion comes from not understanding the difference.

A **vector** file stores the drawing as mathematical instructions: points, curves, fills. It can be scaled up to the side of a building or down to a button without losing sharpness. It's editable — someone can open it and change a colour, separate the symbol from the name, convert it to a single colour. It's the format any production supplier is going to ask for.

A **raster** (or bitmap) file stores a grid of pixels. It has a fixed size. Enlarged, it goes blurry or jagged. It isn't editable beyond surface retouching. It's the format you use where vectors can't go: a Word document, an email signature, a platform that only accepts PNG.

You need both. But the vector is the original and the raster is an export. If all you received was raster, you didn't receive the logo — you received photographs of it.

## The vector formats that have to be there

**AI, or the source file from whatever drawing programme was used.** This is the working file, with layers, with everything still separate. Not everyone can open it, and some studios don't hand it over as a matter of habit. It's worth agreeing this at the outset: the source file is your guarantee that someone else can pick up the work if you stop working with the person who drew it.

**EPS.** The format that printers and older suppliers still ask for by name. Don't use it for anything day to day, but keep it in the folder, because sooner or later somebody will request it.

**Vector PDF.** The most universal and the most practical thing to send to third parties. It opens almost everywhere, keeps the vector intact and doesn't force the recipient to own specialist software. If you can only send one file to a supplier, send this one.

**SVG.** The web format. Small, sharp on any screen, and it can be manipulated with code — changing the colour with CSS, for example. Anyone building your website will ask for SVG, and a clean SVG, without layers of junk exported out of the drawing programme, saves real time.

One detail separates a careful handover from a rushed one: in the final vector files, the type should be **converted to outlines**. If it isn't, the file opened on a computer without the font installed will substitute another one, and the logo reaches the printer with the company name set in a different typeface. It happens more often than you'd expect.

## The raster formats, and what each one is for

**PNG with a transparent background.** The workhorse of daily use. It covers presentations, documents, emails, platforms that won't accept vectors. It should come in several sizes — at least one large version for projection and a small one for interface — and it should come transparent, not with a white background baked in.

**JPEG.** Only makes sense where transparency isn't possible or isn't needed, and where file weight matters. It's no use for sitting on top of anything, because it always brings a rectangle with it.

**Favicon and app icons.** The little square in the browser tab, the icon that lands on someone's phone screen when they save the site. These are tiny sizes, and almost no logo works at them without being redrawn — usually you use the symbol alone, or a single letter, with the fine detail stripped out. If the handover didn't solve this, it will be solved by whoever builds the site, in a hurry and without any criterion.

## The variants: the part most often missing

A logo isn't a shape. It's a set of versions of the same idea, each one for a situation. The handover has to include the versions and has to say when each one is used.

- **Horizontal.** The main version in most cases. It covers website headers, signatures, document footers.
- **Vertical or stacked.** For narrow and square spaces: social profiles, badges, labels, stamps.
- **Symbol on its own.** For when the name is already present in the context, or when the space is so small that the name would be illegible. It should come with the rule that says when using it alone is allowed — without that rule, somebody will put the bare symbol on a leaflet going to people who have never heard of the brand.
- **Reduced version.** This isn't the normal version made small. It's an adjusted drawing: thicker strokes, suppressed detail, letter spacing opened up. Compare the two side by side at 20 px and you'll see why.
- **Wordmark on its own.** Just the name, no symbol. Useful more often than it sounds.

## Dark backgrounds, single colour, and the rest of the colours

This is the section where you can see, in ten seconds, whether the job was closed with care.

**Positive version and dark-background version.** Automatically inverting the colours isn't enough. A logo in a saturated colour on white can be illegible on black, and thin outlines usually need thickening. The dark-background version is an adjusted drawing, not an invert button.

**Single-colour version, positive and negative.** Black on light and white on dark, no gradients, no halftones. This is the one that goes to embroidery, stamps, engraving, single-colour screen printing, hot foiling, the fax machine at a public body. Half of all production suppliers work with nothing else.

**Behaviour on the brand colour.** The logo on the company's own blue, for instance, may disappear. Somebody has to have decided whether in that case you use the white version, a darker tone, or simply don't do it.

**Behaviour on photography.** The case that always comes up and is almost never planned for. The photograph is light in one corner and dark in the other. The handover should include a rule: which version to use, whether there's a protective container, whether a darkening layer is applied to the image.

And then the colour values, which aren't the same on every substrate. **Hex** for web, **RGB** for screen in general, **CMYK** for four-colour printing, **Pantone** for spot-colour printing. These aren't automatic conversions of each other: a Pantone chosen by eye on a screen and never seen in print is a reprint waiting to happen. If the brand is going onto vinyl or textiles, it's worth having the vinyl reference and the embroidery thread colour too.

## The minimum rules that come with the files

It doesn't have to be a fifty-page manual. It has to exist, even if it's a single sheet.

- **Minimum size**, in millimetres for print and pixels for screen, for each version.
- **Clear space**, defined using a unit taken from the logo itself — the height of a letter, half the symbol — so that it scales on its own.
- **Which version to use in which situation**, in plain language.
- **What not to do**, listing the mistakes likely with this particular brand rather than the generic ones.
- **Typeface name and licence**, if the logo uses a commercial typeface, and who holds that licence.

## How a folder that works is organised

The quality of the organisation determines how often somebody uses the wrong file. And almost every brand application error comes from exactly that — not from ignorance of the rules, but from someone opening the 2019 PNG still sitting in an email thread.

A structure that solves it: top-level folders by destination — print, digital, single colour — and inside each of them, files with descriptive, consistent names. Brand name, variant, colour version, format. `muche-horizontal-white.svg` tells anyone who sees it everything they need; `logo-final-v3-OK-2.png` tells nobody anything, including the person who named it.

Add a date or a version number at the root of the folder. And keep the old files in a subfolder called «archive» rather than deleting them — it's the difference between being able to reprint an old piece and having to remake it.

## Signs the handover was done in a hurry

Some indicators that don't lie, and that you can check without knowing anything about design:

- **There are only PNGs or JPEGs.** There's no original. Any physical production will mean redrawing.
- **There's one version only.** Not horizontal and vertical: one. No standalone symbol, no reduced version.
- **There's nothing for dark backgrounds.** The day the brand needs to appear over an image or on a black website, somebody will improvise.
- **The files have an opaque white background.** Open a PNG over any colour. If a white rectangle shows up, the transparency was never done.
- **The PDF opens with a substituted font.** A sign the text wasn't converted to outlines.
- **There are no Pantone or CMYK values.** The brand was thought about for screen only, and the first print run will come out a different colour.
- **The file names are indecipherable.** In six months nobody will know which one is current.
- **Not a single written line arrived.** No minimum size, no clear space, nothing. Every future decision will be taken by whoever happens to have the mouse in their hand.

## What to do before you call the project closed

It's worth one final check, done by you and not by whoever drew it.

Open the folder and look for a vector file. Open it and confirm the company name is in the right typeface. Put the white version on a black background and see if it reads. Shrink the small version down to two centimetres wide and see if it's still legible. Send the PDF to somebody who didn't work on the project and ask them which version they'd use on a business card. If that person hesitates, there's a written line missing somewhere.

A logo handover isn't judged by the beauty of the presentation. It's judged by the number of questions nobody will have to ask a year from now, when the person who drew it is no longer answering the phone.
